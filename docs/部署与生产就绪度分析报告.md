## 一、系统全景概述

### 1.1 项目定位

本项目是一个**面向学习和教学**的推荐系统工程实践，由开发者 `xiaowu` 构建。README 明确指出"用于学习、演示和逐步扩展"。项目并非面向生产的商业系统，而是一个从数据采集到推荐召回的完整技术链路教学项目。

### 1.2 三大模块

| 模块 | 端口 | 定位 | 核心技术栈 |
|------|------|------|------------|
| `backed` | 8922 | 在线服务 | Spring Boot 3.5 + Kafka + Spark Structured Streaming + MySQL + Spring AI |
| `recommendation-trainer` | 8923 | 离线训练 | Spring Boot WebFlux + Spark MLlib ALS + MySQL |
| `example` | 8924 | 教学示例 | Spring Boot + H2/MySQL + Redis + Kafka + Spring AI + Redisson |

## 三、生产就绪度评估

### 3.1 阻断性问题（P0 — 必须解决才能部署）

#### 3.1.1 编译失败：backed 模块依赖错误

```
'dependencyManagement' 中 Spring AI BOM 1.0.0 管理的 artifactId 为
  spring-ai-starter-model-openai

而 backed/pom.xml 第 96 行使用的 artifactId 为
  spring-ai-openai-spring-boot-starter  ← 旧版命名，1.0.0 中已不存在

结果：mvn compile 无法通过，整个多模块项目无法构建
```

**影响**：项目当前**无法编译**，所有模块都受影响（Maven reactor 会校验全部子模块 POM）。

#### 3.1.2 Kafka 推荐结果消费链路断裂

项目文档 `项目缺少什么.md` 明确指出：Spark Structured Streaming 处理后产出的推荐结果写入 Kafka `recommendations` Topic 后，**没有 Consumer 消费这个 Topic**。数据流到控制台输出就断了。

**影响**：推荐结果无法到达用户端，核心推荐链路不闭环。

#### 3.1.3 无安全认证体系

- 所有 4 个 Controller（RecallController、ChatController、StreamController、RecommendationMaintenanceController）**无任何鉴权**：无 Spring Security、无 JWT、无 API Key 校验
- 运维接口（手动触发聚合、清理、流控）**无权限保护**
- `ChatController.test()` 临时测试端点直接暴露 AI 调用入口，标注"验证后删除"但未删除
- 数据库密码 `root/root` 硬编码在 `application.yml` 中

**影响**：任何人可以访问所有 API，包括触发训练、清理数据、消耗 AI API 额度。

#### 3.1.4 无容器化部署方案

- 无 Dockerfile
- 无 docker-compose.yml
- 无 CI/CD 配置（无 Jenkinsfile、无 GitHub Actions、无 GitLab CI）
- 无部署脚本

**影响**：无法进行标准化部署和环境隔离。

### 3.2 严重问题（P1 — 影响生产可用性）

#### 3.2.1 Spark 单机模式，无集群能力

```yaml
spark:
  master: "local[*]"     # ← 单机模式
  executor:
    memory: 1g           # ← 仅 1GB
  driver:
    memory: 1g
```

- 无法水平扩展
- 单点故障：Spark 进程挂掉则流处理完全中断
- 无资源隔离

#### 3.2.2 Kafka 单节点配置

```yaml
kafka:
  topic:
    default-partitions: 1    # ← 仅 1 分区（除 product-ratings 为 3）
    default-replicas: 1      # ← 仅 1 副本
```

- 无多 Broker 集群
- 无高可用保障
- 分区数过少，限制消费并行度

#### 3.2.3 数据库配置为开发模式

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: update    # ← 生产应为 none，DDL 应由 Flyway/Liquibase 管理
  datasource:
    username: root         # ← 明文密码
    password: root
```

#### 3.2.4 测试覆盖严重不足

| 模块 | 测试文件数 | 覆盖情况 |
|------|-----------|----------|
| backed | 2（BackedApplicationTests 空测试 + KafkaConcurrentLoadTest 需外部 Kafka） | 核心业务逻辑零覆盖 |
| recommendation-trainer | 0 | 无任何测试 |
| example | 17（主要覆盖 supplieretl.datasource） | 教学模块反而覆盖最好 |

- 无单元测试覆盖核心推荐逻辑
- 无集成测试
- 无端到端测试
- KafkaConcurrentLoadTest 是压测而非功能验证，且需要外部 Kafka 运行

#### 3.2.5 无监控告警体系

- Actuator 仅暴露 `health` 和 `info` 端点
- 无 Prometheus 指标采集
- 无 Grafana 仪表盘
- 无日志聚合（ELK/EFK）
- 无告警规则

#### 3.2.6 无限流/熔断/降级

- ChatController 无 AI 调用频率限制
- 无 Sentinel / Hystrix / Resilience4j
- 无限流网关
- AI API 调用失败直接返回 500，无降级策略

### 3.3 一般问题（P2 — 影响运维质量）

#### 3.3.1 代码质量问题

| 问题 | 位置 | 说明 |
|------|------|------|
| DTO 字段拼写错误 | `UserRecommendationDTO.windowsEnd` | 应为 `windowEnd`，影响 JSON 契约一致性 |
| 聚合根构造函数 Bug | `UserBehaviorAggregate` | 构造函数接收 List 参数但完全忽略，`rebuild()` 不工作 |
| Producer 配置重复 | `KafkaProducerConfig` | `BUFFER_MEMORY_CONFIG` 重复设置 |
| 骨架代码未完成 | `UserBehavior.java` | 仅有一个 `userId` 字段，无 JPA 映射 |
| 未集成的服务 | `BehaviorAnalysisService` | 定义了异常检测但未被任何代码调用 |
| 临时测试端点 | `ChatController.test()` | 标注"验证后删除"但未删除 |

#### 3.3.2 缺失的 DDL

`JdbcModelVersionReadRepository` 查询 `recommendation_model_version` 表，该表 DDL 仅在 trainer 模块的 `database/` 目录下存在，backed 模块没有。若单独部署 backed 模块可能遗漏此表。

#### 3.3.3 配置硬编码

- OpenAI 代理地址 `127.0.0.1:7890` 硬编码
- AI 模型名称在 ChatController 中硬编码为 `gpt-5`
- Spark checkpoint 路径 `./spark-checkpoint` 相对路径，不适合容器化

#### 3.3.4 无配置中心

- 所有配置通过 `application.yml` / `application-prod.yml`
- 无 Spring Cloud Config / Nacos / Apollo
- 配置变更需要重新部署

#### 3.3.5 无日志规范

- 使用 SLF4J 但无统一日志格式
- 无 Logback 生产配置文件
- 无结构化日志（JSON format）

## 四、总结与建议

### 4.1 总体结论

> **本项目当前状态为"教学级原型"，综合生产就绪度约 25%，不适合生产部署。**

核心判断依据：

1. **无法编译** — backed 模块 Spring AI 依赖 artifactId 错误，整个项目构建失败
2. **链路断裂** — 推荐结果写入 Kafka 后无 Consumer 消费，核心闭环不完整
3. **零安全防护** — 无认证、无鉴权、无限流，所有 API 裸奔
4. **零部署自动化** — 无 Dockerfile、无 CI/CD、无部署脚本
5. **测试几乎空白** — 核心业务逻辑零测试覆盖
6. **单点架构** — Spark/Kafka/MySQL 均为单节点，无高可用
7. **项目定位** — README 和文档均明确标注"学习、演示"用途

### 4.2 优点与价值

尽管不适合生产部署，但本项目在以下方面具有显著价值：

- **架构设计优秀**：DDD 分层、领域接口与实现分离、幂等设计贯穿全链路
- **技术选型前沿**：Spring Boot 3.5 + Spark 4.0 + Spring AI 1.0 + Java 17/21
- **注释质量极高**：大量设计决策说明，可作为学习教材
- **文档体系完整**：14 篇设计文档覆盖架构、算法、Kafka 最佳实践、面试场景
- **教学示例丰富**：example 模块含 JVM 内存、支付幂等、Kafka 消费幂等、秒杀、ETL 等完整示例
- **企业级 Kafka 配置**：幂等生产者、LZ4 压缩、手动 offset 提交、分区有序
